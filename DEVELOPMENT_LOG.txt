  - Timeframes 1 / 5 (default) / 15 / 30 min via dropdown.
  - Paper mode with live option prices and 0.5% slippage.
  - SQLite trades.db; full Indian tax ledger; metrics (Profit Factor, Sharpe,

  - Three tabs: Dashboard, Strategy & Setup, Reports & Logs; PDF/CSV export.

 3. DEVIATIONS FROM THE ORIGINAL SPEC (AND WHY)
--------------------------------------------------------------------------------

 3.1 upstox_client.py renamed to upstox_broker.py  (approved by user)
     The official SDK package is itself named "upstox_client". A local file
     with the same name shadows it: "import upstox_client" loaded our own file
     (verified with importlib.util.find_spec). The SDK's internal modules also
     import "upstox_client.*", so no simple alias works. Never recreate a file
     named upstox_client.py in this folder.

 3.2 Orders use the SDK's V3 order API (OrderApiV3 + PlaceOrderV3Request)
     Verified on SDK 2.23: the v2 PlaceOrderRequest has NO market_protection
     field. Upstox now requires market protection on API MARKET orders, so v2
     market orders (including exits) would be rejected. V3 supports
     market_protection (set to -1 = automatic) and slice (set to False).
     V3 returns data.order_ids (a list); the code requires exactly one id.

 3.3 5-min and 15-min candles are built locally
     The Upstox v2 historical API only offers 1minute and 30minute intraday
     intervals. All timeframes are therefore built from 1-minute candles,
     resampled and aligned to 09:15 IST (pandas resample, origin=start_day,
     offset=15min).

 3.4 Instrument master uses JSON (NSE.json.gz), not CSV
     Upstox documentation marks the CSV files as deprecated.

 3.5 PDF builder lives in database.py
     To keep the five-module structure instead of adding a report.py.

 3.6 Safety features added beyond the spec
     - No new entries after 15:00 IST.
     - LIVE mode must be armed by typing "LIVE" in a dialog.
     - Mode and index cannot be changed while a position is open.
     - Engine "HALT" state on uncertain live entry or failed exit; must be
       acknowledged manually after checking the broker.
     - Signal ignored if the spot price is older than 5 seconds.

 6. ARCHITECTURE AND THREADING
--------------------------------------------------------------------------------

 Threads
   - Tk main thread: GUI only. Never calls the network.
   - "ui-io" pool (2 workers): OAuth login, broker connect/validate,
     instrument download. Results are handed back with self.after(0, ...).
   - "engine-loop" thread: runs every 1 s (_tick_clock): day rollover, 15:15
     square-off, stale-spot REST fallback, bar-close scheduling.
   - "engine" pool (4 workers): candle refresh, entry, exit.
   - "feed-A-SPOT" and "feed-B-OPTION" threads: one per WebSocket channel.

 Data flow
   WebSocket tick -> TradingEngine._tick() -> updates State under RLock;
   if a position is open and the spot crosses SL/TP -> request_exit().
   GUI polls engine.snapshot() every 500 ms and drains engine.events queue
   for the Event Log.

 Concurrency guards
   - threading.RLock protects State.
   - threading.Event "exiting" ensures only one exit runs at a time.
   - The daily-limit reservation is an atomic SQLite INSERT on a PRIMARY KEY
     (day), so concurrent signals cannot both enter.

 7. MODULE DETAILS
--------------------------------------------------------------------------------

 7.1 database.py
   Tables
     sessions(day PK, state, mode, detail)
        One row per trading day = the daily trade slot.
        state: RESERVED -> ENTRY_SUBMITTING (live) -> OPEN -> EXHAUSTED
               or BLOCKED (entry failed/interrupted).
        NOTE: the slot is per day regardless of mode: a paper trade also
        consumes the live slot for that day.
     trades(id, day UNIQUE, mode, status OPEN/CLOSED, payload JSON,
            entry_time, exit_time, gross, taxes, slippage, net)
     events(id, time, level, message)       Event log history.
     settings(key PK, value)                 UI settings (not secrets).
   FeeSchedule (Decimal math, rounded to paise)
     brokerage   Rs 20 per executed order (default 2 orders per trade)
     exchange    0.03503% of turnover (buy + sell premium)   <- ASSUMPTION
     sebi        0.0001% of turnover (Rs 10 per crore)
     stt         0.125% of sell premium value
     stamp       0.003% of buy premium value
     gst         18% of (brokerage + exchange + sebi)
     Verify these rates periodically; exchange charges change.
   metrics()
     net, equity, profit_factor (inf if no losses), sharpe (daily returns,
     sqrt(252) annualised, None until >= 2 days), max_dd %, win_loss ratio,
     avg_duration (minutes), total taxes, total slippage, equity curve,
     drawdown series.
   export_csv(), build_pdf() (ReportLab, landscape A4, KPI table + full tax
   ledger with each charge component).

 7.2 upstox_broker.py
   SPOT_KEYS     NIFTY -> "NSE_INDEX|Nifty 50", BANKNIFTY -> "NSE_INDEX|Nifty Bank"
   TokenVault    Stores {"day", "token"} in Windows Credential Manager
                 (keyring, service "StratTerminal.Upstox", account = SHA-256 of
                 API key). Token reused only if saved today (IST). Refuses to
                 store if no secure keyring backend exists.
   OAuthLogin    Opens the Upstox login page in the browser; runs a one-shot
                 local HTTP server on the registered loopback redirect
                 (default http://127.0.0.1:8765/callback); validates a random
                 "state" value (CSRF protection); 180 s timeout; exchanges code
                 for token via LoginApi.token.
   round_strike  floor(price/step + 0.5) * step (exact .5 rounds up).
   InstrumentMaster
                 Downloads NSE.json.gz once per day to .cache (atomic write);
                 option() picks segment NSE_FO, matching CE/PE,
                 underlying_key = spot key, strike = ATM, nearest expiry >= today.
                 Returns key, symbol, lot_size, strike, expiry, freeze qty.
   aggregate_candles
                 1-min rows -> IST index, dedupe, keep 09:15-15:29,
                 resample to N minutes aligned to 09:15.
   FeedChannel   One per channel. SDK auto-reconnect DISABLED; own loop:
                 backoff 0.5 s doubling to max 30 s (reset after a connection
                 lasts > 60 s); watchdog reconnects if no packet for 35 s.
                 Mode "ltpc"; ticks need ltp > 0 and an ltt timestamp.
   UpstoxBroker
     validate()     UserApi.get_profile.
     candles()      Past ~27 days of 1-min history (cached per index/day) +
                    today's intraday; drops unfinished bars; requires >= 121
                    settled bars (EMA21 + 100 padding); returns last 500.
     quote()        Full market quote; rejects price <= 0 or trade older
                    than 10 s.
     market_order() V3 MARKET, product "I" (intraday), DAY, slice False,
                    market_protection -1.
     order_status() / order_book() / cancel() (V3) / positions().
     stream()       Starts/replaces a named FeedChannel.

 7.3 strategy.py
   Constants   SIGNAL_START 09:30, ENTRY_CUTOFF 15:00, SQUARE_OFF 15:15,
               MARKET_CLOSE 15:30, SLIPPAGE 0.5%, SL 1.5 ATR, TP 3.0 ATR,
               ATR length 14, INTERVALS {1,5,15,30}.
   Pure functions (unit tested)
     indicators()  ema9, ema21, atr via pandas-ta.
     crossover()   Uses only the latest CLOSED bar; bar must be from today,
                   start at/after 09:30, be fresh (within one interval of
                   closing) and before 15:00. Returns "CE"/"PE"/None.
     risk_levels() stop/target from entry spot and ATR (rejects bad ATR).
     exit_reason() Touch-based (<= / >=) SL/TP checks on spot.
     lots_for()    "Fixed Lots" or "Max Risk %" (full premium treated as the
                   worst-case loss); capped by exchange freeze quantity.
   TradingEngine
     attach()       Recover state from DB, start feeds and loop.
     _tick_clock()  Every second. At 15:15 requests square-off. If spot is
                    older than 5 s during a position, polls REST quote.
                    At each bar boundary (+3 s) runs on_bar_close().
     on_bar_close() Refresh candles -> crossover() -> enter().
     enter()        Checks halt/position/arming/spot freshness -> reserves the
                    day atomically -> refreshes master if stale -> picks
                    contract -> quotes -> sizes ->
                      PAPER: fill = quote * 1.005
                      LIVE:  journals ENTRY_SUBMITTING, places MARKET BUY,
                             waits up to 20 s for fill (cancels remainder).
                    Saves trade, starts channel B. On ANY error the day is
                    BLOCKED (never retried); live errors also HALT.
     _exit()        PAPER: option price (tick <= 5 s old, else REST) * 0.995.
                    LIVE: up to 3 attempts; each attempt first reads broker
                    positions and sells only the remaining quantity; fails ->
                    HALT "EXIT FAILED - CLOSE POSITION MANUALLY NOW".
                    Records fees with the actual order count.
     recover()      Reloads an OPEN trade after restart; an interrupted
                    entry (RESERVED/ENTRY_SUBMITTING) blocks the day and, if
                    live, halts.

 12. KNOWN LIMITATIONS AND RISKS
--------------------------------------------------------------------------------

   - Nothing has been run against real Upstox yet (see section 1).
   - Reconnecting a WebSocket cannot recover ticks missed during an outage;
     a spot move through SL/TP during a gap is only seen on the next tick or
     REST poll (stale-spot fallback polls every second after 5 s).
   - MARKET orders can slip; market protection may cause partial/no fills.
   - The app must stay open: no exits or 15:15 square-off while closed.
   - Signals use REST 1-minute candles fetched ~3 s after each bar closes,
     not candles built from WebSocket ticks.
   - On restart, an open LIVE position is restored from the local DB only;
     it is not reconciled against broker positions automatically.
   - One trade slot per day shared by PAPER and LIVE.
   - Exchange transaction charge rate (0.03503%) is an assumption.
   - The instrument master is downloaded at connect and re-checked at entry
     if the date changed; there is no separate scheduled 09:15 download job.
   - Upstox algo-trading rules (registration, X-Algo-Name, static IP) were not
     configured; check current requirements before live use.
   - Unrealised P&L on the dashboard excludes fees.
   - Windows console cannot print the rupee sign without
     PYTHONIOENCODING=utf-8 (GUI is unaffected).

 14. ADDENDUM 2026-10-29: BACKTEST ("DUMMY RUN") FEATURE
--------------------------------------------------------------------------------

 Purpose  Replay past days with real Upstox history using the SAME rules as
          the live engine, and show results in the Reports tab.

 Where
   upstox_broker.py  rows_to_frame(), resample_bars() (aggregate_candles now
                     uses them); UpstoxBroker.spot_minutes(index, start, end);
                     UpstoxBroker.backtest_option(index, day, side, strike):
                     finds the nearest expiry on/after `day` from
                     ExpiredInstrumentApi.get_expiries + OptionsApi active
                     contracts, then fetches the ATM contract's 1-min candles
                     (expired-instruments endpoint if expired, else normal
                     history). Results cached per run.
   strategy.py       simulate_day() and run_backtest().
   database.py       Database.reset() (used only on backtest.db).
   gui.py            Reports tab: "Paper/Live | Backtest" ledger selector and
                     a Backtest bar (From/To default = last Mon-Fri, Run).
   backtest.db       Separate DB; cleared at the start of each run. Never
                     touches trades.db.

 Simulation rules
   - Spot 1-min history from (start - 20 days) is resampled to the chosen
     timeframe; >= 121 prior bars required (else the day is skipped).
   - Signal: crossover() evaluated at each bar close + 3 s (same 09:30 filter,
     15:00 entry cutoff, one trade per day).
   - Entry: next minute's spot OPEN; option price = that minute's option open
     (or last earlier close) * 1.005.
   - Exit: walk 1-min spot bars; SL/TP via bar high/low. If both are touched
     in the same minute, STOP_LOSS is assumed (conservative). Option exit =
     that minute's close * 0.995. Otherwise square-off at 15:15 open.
   - Fees: same FeeSchedule (2 orders). Sizing uses running backtest capital.

 Requirements / limits
   - Needs an Upstox login (history requires an access token).
   - Expired-contract data may require a specific Upstox plan; if the API
     refuses, the run reports "Expired-contract data unavailable".
   - 1-minute bars cannot show the exact tick order inside a minute, and
     option prices are bar opens/closes, not real fills.
   - v2 1-minute history covers a limited recent window; very old ranges fail.

 Tests  tests/test_strategy.py BacktestTests (synthetic data):
   - bullish rally -> CE entry after 09:35 -> TARGET, 0.5% slippage both sides
   - SL and TP in the same minute -> STOP_LOSS
   Total suite: 15 tests, all passing.

 15.1 SIL harness  tests/sil_harness.py
   Runs the REAL TradingEngine (no code changes) against:
   - make_minutes(seed): seeded 1-min OHLC, ~1% daily range, drifting regimes.
   - premium(): deterministic option price = intrinsic + bell-shaped time
     value, 0.05 tick.
   - SimBroker: the same interface as UpstoxBroker (candles, quote, market_order,
     order_status, cancel, positions, stream, master). Fault injection:
     order_faults = "reject" | "raise" | "partial" | "pending"; outage flag;
     latency (seconds) on orders/positions.
   - Virtual clock; each minute is stepped at seconds 0, 3, 15, 30, 45.
     Ticks: open @0, extremes @15/@30, close @45. While a position is open
     the ADVERSE extreme comes first (matches the backtest's SL-first rule).
   - Option quote = price from the minute open before second 10, else from the close.
   - SyncPool runs engine work inline for determinism (real thread pool used
     in the concurrency tests).

 15.2 Back-to-back  tests/test_b2b.py
   Live engine (SIL) vs run_backtest() on identical data, compared field by

 16.0 SECURITY FIX (found while integrating the portfolio stream)
   upstox-python-sdk's websocket feeders (market data AND portfolio) call
   run_forever(sslopt={"cert_reqs": CERT_NONE, "check_hostname": False}) while
   sending "Authorization: Bearer <token>" -> token theft possible on hostile
   networks. upstox_broker._enforce_websocket_tls() subclasses
   websocket.WebSocketApp at import time and forces CERT_REQUIRED +
   check_hostname + certifi CA bundle. REST already verified TLS
   (Configuration.verify_ssl=True). Test: TransportAndStreams.test_websocket_tls_is_forced_on.
   Re-check this whenever the SDK is upgraded.

 16.1 Separate PAPER / LIVE daily limit
   sessions PK and trades UNIQUE are now (day, mode). Database._migrate()
   converts v1 databases in place (copies rows, drops old tables); idempotent.
   API change: session(day, mode), session_state(day, mode, state, detail),
   active_trade(mode=None).

 16.2 Editable strategy parameters (strategy.Params, frozen dataclass)
   ema_fast/ema_slow, atr_length, sl_atr/tp_atr, signal_start/entry_cutoff/
   square_off (HH:MM), slippage_pct, trend_filter, trend_ema, adx_length,
   adx_min, bar_source, backstop, backstop_pct. validate() enforces ranges and
   09:15 <= start < cutoff <= square-off < 15:30. warmup = longest indicator +
   100 (default 121, unchanged). Stored as JSON in settings key "params".
   Each trade stores the params used (trade["params"]). Exit reason for the
   time exit is SQUARE_OFF_<HHMM>. Old constants (SIGNAL_START, SLIPPAGE, ...)
   and indicator columns ema9/ema21 were replaced by Params and
   ema_fast/ema_slow.

 16.3 Trend filter (Off / EMA / ADX / EMA+ADX)
   EMA: CE needs close > trend EMA, PE needs close < trend EMA. ADX: ADX >= min.
   NaN indicator -> no trade. VWAP/volume filter NOT possible: NSE index spot
   has no traded volume (documented in the GUI).

 16.4 Tick-built bars (bar_source "Ticks", default)
   TickBars aggregates feed-A ticks into 1-min OHLC. A bar is used only if every
   minute has ticks and the first tick of the bar's first minute is <= 30 s
   late; otherwise on_bar_close falls back to REST candles. The tick bar is
   appended to the last REST frame only if it is contiguous (no gap).
   Measured: >5x fewer REST candle calls; identical trades to REST bars.

 16.5 Real-time order updates
   upstox_broker.OrderStream (PortfolioDataStreamer, same backoff, no packet
   watchdog because the socket is silent when idle). UpstoxBroker caches
   updates; order_status() returns a cached terminal state, else REST;
   _await_fill() waits on the update condition instead of sleeping.

 16.6 Broker-side protective stop-loss ("backstop", LIVE only, default on)
   After a filled live entry: SELL SL-limit (SL-M is not allowed for NSE
   options) with trigger = entry premium x (1 - backstop_pct), limit = 90 % of
   trigger, 0.05 tick. Any app exit first cancels it and WAITS for a terminal
   state (5 s); if it cannot be confirmed the exit aborts and HALTS (prevents a
   double SELL / naked short). Its own fills are counted in the exit. If the
   exchange fires it, the order update triggers an exit that records
   BACKSTOP_SL without sending another SELL. Placement failure only warns.
   Limitation: a gap through the limit price can leave it unfilled.

 16.7 Live startup reconciliation + Manual close
   reconcile() (on attach when LIVE is relevant, on switching to LIVE, and via
   the Reconcile button): app open but broker flat; quantity mismatch;
   untracked position from today's app-tagged BUY -> HALT + CRITICAL.
   manual_close(price): refuses bad prices, refuses LIVE unless the broker is
   flat (cancels backstop first), records MANUAL_CLOSE, clears HALT.
   Closes gap 15.7.

 16.8 Fee-aware live P&L, alerts
